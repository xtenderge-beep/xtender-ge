# Услуги исполнителя и рассылка заявок

## Работа менеджера

В карточке исполнителя и форме модерации менеджера можно выбрать несколько услуг.
У услуги «Грузчики» есть условие «Погрузка только вместе со своим транспортом».
Для него обязательно выбрать перевозки. Без этого условия услуга участвует в
самостоятельной рассылке грузчикам. Профиль, баланс и история исполнителя общие.

Перед первой рассылкой составной заявки в административной карточке нужно сохранить
все потребности и, при необходимости, размер транспорта. После первой рассылки этот
набор не редактируется: клиент или модератор может закрывать потребности отдельно.
Старый сценарий выбора категорий по очереди сохранён для совместимости; зависимые
услуги подбираются только когда обе потребности явно открыты.

Telegram показывает новых получателей, фактический результат запуска и действия
исполнителей. Кнопка результатов показывает последние запуски и получателей прямо
в Telegram. Подробная история также доступна в административной карточке.
Повтор ошибок создаёт отдельный запуск только для подходящих исполнителей с
подтверждённой неудачной отправкой. Повторное нажатие не создаёт повторного списания.

## Правила подбора

| Открытые потребности | Получатели |
| --- | --- |
| Только грузчики | Самостоятельные грузчики |
| Только транспорт | Подходящие перевозчики |
| Транспорт и грузчики | Перевозчики, самостоятельные грузчики и грузчики со своим подходящим транспортом |

Размер проверяется по выбранному тиру. Если в заявке задан размер, транспорт с
неизвестным размером не считается подходящим. Когда транспорт закрыт, условная
погрузка перестаёт подходить. Если закрыты грузчики, перевозка остаётся доступной.
Правила используются при подборе, непосредственно перед отправкой, при раскрытии
контакта и в списке заявок исполнителя. Страница старой ссылки показывает актуальные
потребности. Фактический исполнитель и результат сделки не фиксируются.

## Хранение и статистика

- `master_services` хранит выбранные услуги и `requires_own_transport`.
  Старые поля `masters.category` и размера сохраняются как совместимая проекция.
- `orders.target_categories` и `order_category_closures` задают независимые потребности;
  `orders.requirements` хранит настройку размера. Устаревшие кнопки проверяют версию заявки.
- `dispatch_runs` хранит группу, размер, язык, инициатора и связь с повторным запуском.
  Административный вход общий, поэтому его инициатор обозначается `admin`;
  Telegram сохраняет ID нажавшего пользователя.
- `dispatch_deliveries` хранит снимок услуг, предложенные потребности, канал и результат.
  Изменение профиля не переписывает новую историю. Старые записи используют сохранённое
  доказательство отправки либо единственную историческую группу; иначе услуга неизвестна.
- Принятие сообщения каналом не означает прочтение. Открытие страницы и нажатия телефона
  или WhatsApp считаются отдельно. Общий показатель контакта — уникальные исполнители.
  Группы услуг могут пересекаться; контактный клик не приписывается конкретной услуге.

## Ошибки и ограничения

Неопределённая отправка (например, таймаут либо сбой фиксации после принятия каналом)
остаётся `pending` с причиной. Она блокирует автоматический повтор через любой канал:
иначе можно отправить дубликат. Для таких случаев требуется проверка журналов оператора.
После остановки процесса незавершённые записи также сохраняются; фонового работника
для автоматического восстановления в этой реализации нет.

Одна строка `van` по-прежнему описывает один набор характеристик транспорта профиля.
Отдельный парк из нескольких автомобилей не вводится. Саморегистрация остаётся
первичной заявкой; несколько услуг назначаются при модерации.

## Внедрение и проверка

Новые колонки добавляются идемпотентными командами в конце `schema.sql`, который
приложение применяет при запуске. Код и миграцию необходимо выпускать вместе.
Изменения не требуют новых пакетов.

Ключевые проверки: `multi-service-dispatch.test.js`, `multi-service-ui.test.js`,
`dispatch-language.test.js`, `order-contact.test.js`, `order-category-close.test.js`,
`funnel-by-category.test.js`, `lead-charge-evidence.test.js`.
Тесты используют pg-mem и имитацию внешних каналов, а не рабочую базу или реальные SMS.
