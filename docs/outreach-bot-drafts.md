# Анкеты исполнителей от SMS-бота

Ответ сайта на ТЗ «черновики анкет мастеров и страница подтверждения» (2026-11-12). Бот владельца переписывается
с мастером, по API создаёт черновик анкеты, получает короткую ссылку и сам отправляет её мастеру в SMS. Мастер
открывает ссылку, проверяет и правит анкету, ставит галочки и подтверждает **кодом из SMS сайта**. Дальше —
обычная регистрация: профиль уходит на модерацию, как с `/join`.

Сайт при создании черновика ничего не отправляет. Первое SMS с кодом уходит только после того, как мастер сам
нажал «Подтвердить» на странице.

Код: `src/services/providerDraft.service.js`, `src/routes/outreachDraft.routes.js`, страница
`src/views/provider-draft.ejs`, тексты страницы `src/config/provider-draft-copy.js`, админка
`/admin/outreach/drafts`. Тест: `tests/provider-drafts.test.js`.

## 1. Доступ

- Базовый адрес: `https://xtender.ge/api/outreach/…`
- Ключ: заголовок `Authorization: Bearer <ключ>`. Ключ выпускает владелец в админке:
  **Рассылки → Анкеты от бота → Выпустить ключ**. Ключ показывается один раз, на сервере хранится только его
  отпечаток. Новый ключ сразу отключает прежний. Ключ в адресе запроса (`?key=`) сайт отклоняет с `400 key_in_url`.
- Запасной ключ можно задать переменной окружения `OUTREACH_API_KEY` (например, для отдельной тестовой копии сайта).
- До 60 запросов в минуту, сверх этого `429 rate_limited`.
- Ответы — JSON. Ошибка: `{ "error": "<код>", "message": "<текст по-английски>", …подробности }`.
- Тестовый режим: `"test": true` в черновике. Такой черновик не попадает в счётчики админки, а профиль после
  подтверждения сразу тестовый (`masters.is_technical`): в каталог и рабочие заявки он не попадает.
  SMS с кодом при этом настоящее — на номер из черновика.

## 2. Справочник

`GET /api/outreach/services` — включённые на сайте услуги, те же коды, что в `/llms.txt`:

```json
[{ "code": "movers", "name": { "ka": "მუშები", "ru": "Грузчики", "en": "Movers" } }]
```

`GET /api/outreach/cities` — города, открытые на сайте (сейчас только Тбилиси):

```json
[{ "id": 1, "slug": "tbilisi", "name": { "ka": "თბილისი", "ru": "Тбилиси", "en": "Tbilisi" } }]
```

С выкладкой на сайте появляются шесть направлений (решение владельца 2026-11-12): «Котлы и отопление», «Газовое
oборудование», «Окна и двери», «Электрика», «Кровля», «Покраска и штукатурка». Их коды (`svc_…`) бот берёт из справочника
по названию, а не прописывает заранее: коды создаются на сайте при выкладке. Направления, которых в справочнике нет, бот
передаёт текстом в `other_services`. Модератор увидит их в карточке исполнителя и в Telegram.

## 3. Создать черновик

`POST /api/outreach/drafts`

```json
{
  "phone": "+995597749378",
  "name": "Zurab Kvrivishvili",
  "type": "master",
  "services": ["movers"],
  "other_services": ["Котлы и отопление"],
  "description": "Укладка плитки и керамогранита, ванные под ключ.",
  "experience": "12 лет",
  "city": "Тбилиси",
  "districts": ["Сабуртало", "Ваке"],
  "languages": ["ka", "ru"],
  "has_vehicle": false,
  "lang": "ka",
  "source": "fb_group_remont",
  "external_id": "sup_000123",
  "provider_agreed": true,
  "test": false
}
```

Обязательные поля: `phone`, `services` или `other_services`, `description`, `city`, `lang`, `provider_agreed`.

| Поле | Правило |
|---|---|
| `phone` | Грузинский номер в любой записи (`+995…`, `995…`, 9 цифр, с пробелами). Хранится как `+9955XXXXXXXX`. |
| `provider_agreed` | `true` — **только после того, как мастер ответил боту «да, делайте анкету»**. Без этого `400 provider_not_agreed`: до согласия мастера его данные на сайте не хранятся. |
| `services` | Коды из справочника. Неизвестный код — `400 unknown_service` со списком `unknown`. |
| `other_services`, `districts` | Список строк (до 20, каждая до 100 знаков) или строка через запятую. |
| `description` | До 2000 знаков, **без номера телефона** (`400 description_has_phone`): клиенты открывают номер через каталог. |
| `experience` | До 100 знаков. После подтверждения дописывается к описанию строкой «Опыт: …» на языке анкеты. |
| `city` | Название на любом из трёх языков, slug или id; можно списком. Город, закрытый на сайте, — `400 unknown_city` со списком `cities`. |
| `languages` | Коды `ka ru en hy az tr uk`. Можно не присылать: мастер отметит сам. |
| `type` | `master` \| `vehicle` \| `shop` (или список), `has_vehicle: true` добавляет `vehicle`. Подсказка модератору, как «Кто вы?» на `/join`. |
| `lang` | `ka` \| `ru` \| `en` — язык страницы анкеты (на странице есть переключатель). |
| `source` | Метка источника: латиница, цифры, `_ . : -`, до 80 знаков. По ней фильтр в админке. |

Ответ `201` (новый черновик) или `200` (повтор с тем же номером):

```json
{ "draft_id": "d_8f3k2abc", "status": "draft", "confirm_url": "https://xtender.ge/c/K7P2QXAB", "expires_at": "2026-11-26T12:00:00.000Z" }
```

- Ссылка короткая: `xtender.ge/c/` + 8 знаков (21 знак без `https://`). Знаки без похожих (нет 0/O, 1/I/L),
  регистр не важен. Ссылку угадать нельзя (31⁸ вариантов, и не больше 30 неверных попыток в час с одного адреса).
- Ссылка действует **14 дней**. Срок не продлевается повторным POST.
- **Один номер — один черновик.** Повторный POST с тем же номером обновляет поля и возвращает ту же ссылку.
  Если прежний черновик истёк, повторный POST создаёт новую ссылку на новые 14 дней.
- Номер уже зарегистрированного исполнителя (с `/join`, от менеджера, от бота) — `409 already_registered`
  с полем `status` (`confirmed` / `active` / `rejected`). Боту такому мастеру писать не нужно.
- Номер из списка отказа — `409 opted_out`.

## 4. Изменить черновик

`PATCH /api/outreach/drafts/{draft_id}` — те же поля, все необязательные; номер менять нельзя. Только пока
черновик не подтверждён, не отклонён и не истёк, иначе `409 not_editable` с полем `status`.

## 5. Статус

`GET /api/outreach/status?phone=%2B995597749378` (незакодированный `+` тоже понимается):

```json
{ "phone": "+995597749378", "status": "confirmed", "draft_id": "d_8f3k2abc",
  "confirmed_at": "2026-11-13T09:41:00.000Z", "free_until": "2027-01-12T09:41:00.000Z", "profile_url": null,
```

| Статус | Значение |
|---|---|
| `none` | Номера на сайте нет (или профиль из черновика удалён администратором) |
| `draft` | Черновик создан, мастер ссылку не открывал |
| `opened` | Мастер открыл ссылку, но не подтвердил |
| `confirmed` | Подтвердил кодом, профиль на модерации |
| `active` | Прошёл модерацию |
| `rejected` | Профиль заблокирован модератором, поле `reason` |
| `declined` | Мастер нажал «Не интересно» на странице |
| `expired` | 14 дней прошли без подтверждения, анкета стёрта; поле `expired_at` |
| `opted_out` | Бот передал отказ («нет / STOP») |

Зарегистрированный профиль важнее остального: если мастер зарегистрировался сам, статус — по профилю.
`profile_url` всегда `null`: отдельной публичной страницы исполнителя на сайте нет, профиль виден в каталоге.

`lead_sms` и `telegram` — только когда профиль есть (иначе `null`). `lead_sms: true` — SMS о заявках включены (галочка при
подтверждении или позже в кабинете) и не на паузе. `telegram: true` — привязан Telegram, туда заявки приходят и без SMS.
Если оба `false`, заявки мастеру не придут: бот может напомнить включить SMS или Telegram в кабинете. Включение
в кабинете в `changes` не попадает, поэтому таких мастеров бот проверяет по `status`.

Массовый вариант: `GET /api/outreach/changes?since=2026-11-13T00:00:00Z` — список `{ phone, status, changed_at }`
(текущий статус, плюс `lead_sms` и `telegram`), чьё состояние менялось после `since`: черновик, отказ, решение модератора по профилю из
черновика. До 1000 строк, по возрастанию `changed_at`. Вебхука нет.

## 6. Отказ

`POST /api/outreach/optout` с `{ "phone": "+995…", "reason": "просил не писать" }` — когда мастер ответил боту
«нет / не пишите / STOP». Номер попадает в список отказа, неподтверждённый черновик стирается, факт отказа
пишется в журнал согласий (`OUTREACH_OPT_OUT`). Работает и для номера без черновика. Зарегистрированный профиль
это не трогает: его SMS выключаются в кабинете или по ссылке «Stop».

## 7. Страница `/c/{token}`

Вёрстка под телефон (проверена на 320, 360 и 412 px на ka / ru / en), язык из `lang` черновика,
переключатель ka / ru / en.

1. Заголовок «Ваша анкета на xtender.ge», строка «Первые 2 месяца бесплатно: заявки клиентов приходят вам по SMS».
2. Анкета, всё правится на месте: имя; услуги (предложенные отмечены, остальные — под «Другие услуги +»);
   «Что ещё делаете»; описание; опыт; города и районы; языки. Телефон показан частично (`+995 597 •• •• 78`)
   и не редактируется.
3. Те же тексты и галочки, что на `/join`, **все сняты**: условия (оферта), политика конфиденциальности,
   «Получать заявки по SMS», «Получать предложения Xtender».
4. «Подтвердить» активна, только когда отмечены условия и политика. Нажатие сохраняет правки и отправляет код
   на номер из черновика (не на номер, введённый на странице: его там ввести нельзя).
5. Код из SMS → профиль создаётся как с `/join` и уходит на модерацию; модератору — сообщение в Telegram;
   мастеру — обычная SMS о регистрации со ссылкой на кабинет и «Stop»; на этом телефоне он сразу входит в кабинет.
   Экран «Спасибо! Анкета отправлена на проверку.» и «Заявки будут приходить по SMS» (или, если SMS о заявках
   не отмечены, — «включите их или Telegram в кабинете»).
6. Внизу «Не интересно, удалите мои данные» → подтверждение → анкета стирается, номер в списке отказа, статус `declined`.

По подтверждённой ссылке страница пишет «Анкета уже подтверждена» и ведёт ко входу; по истёкшей — «Срок ссылки
истёк» и ведёт на `/join`; по удалённой — «Данные удалены».

## 8. Запись согласий

Подтверждение кодом пишет в журнал согласий (`sms_consent_logs`, с цепочкой отпечатков и архивом
`/admin/evidence`) то же, что регистрация на `/join`: дату и время, IP, браузер, отправку кода через шлюз,
текст и версии оферты и политики, выбор по двум SMS-разрешениям. В снимке согласия дополнительно
`signup_path: "outreach_draft"` и `draft_id` — видно, что регистрация шла по ссылке от бота.

## 9. Хранение данных

- До подтверждения анкета лежит только в `provider_drafts.data`.
- При подтверждении, отказе или по истечении 14 дней `data` стирается; остаются номер, статус и даты — чтобы
  бот видел итог и не писал повторно. Истёкшие черновики стираются раз в час.
- Список отказа (`outreach_optouts`) — только номер, причина и откуда отказ.

## 10. Профиль после подтверждения

- `masters.free_until` = подтверждение + 60 дней. Пока это только дата для владельца в админке: платный режим
  по-прежнему включает администратор в карточке (`paid_mode`), сейчас все исполнители и так бесплатны.
  «Бесплатный период кончается за 14 дней» — счётчик на странице «Анкеты от бота» (по прежнему правилу владельца
  о предупреждении за 14 дней). SMS исполнителю о конце периода сайт не шлёт: текст не утверждён.
- `masters.signup_source` — `source` бота; `masters.signup_hint` — что бот предложил: услуги, другие
  направления, районы. **Услуги назначает модератор**, как и с `/join`: бот только подсказывает (видно в карточке
  исполнителя и в Telegram).
- **Номер в каталоге.** После одобрения профиль с номером стоит в каталоге. Номер показан частично; целиком его
  видит клиент, который подтвердил свой телефон кодом из SMS (так сайт отсекает роботов и считает звонки).
  **Клиент не платит никогда.** Исполнителю в бесплатном режиме это ничего не стоит. Бесплатный период у каждого
  исполнителя свой: платный режим администратор включает в карточке только после того, как исполнитель сам принял
  тарифы в кабинете; тогда каждый новый клиент, открывший номер, и каждая заявка списываются с баланса по
  принятому тарифу. Сами по себе деньги не списываются. Цены бот не называет — такие вопросы передаёт владельцу.
  (В отчёте 2026-11-12 я написал «номер скрыт и открывается клиенту только платно» — это было неточно.)

## 11. Админка

**Рассылки → Анкеты от бота** (`/admin/outreach/drafts`): счётчики (создано, открыли, подтвердили, в каталоге,
«не интересно», просили не писать, истекло, бесплатный период кончается за 14 дней — без проб бота), фильтр по
источнику и статусу, список с датами и ссылкой на профиль, выпуск ключа API.

## 12. Чем ответ отличается от ТЗ

| В ТЗ | На сайте | Почему |
|---|---|---|
| Подтверждение по ссылке, код — на выбор | Код из SMS сайта обязателен | Ссылку бот шлёт с личного телефона, и записи об отправке на сайте нет. Код через шлюз сайта доказывает, что подтвердил владелец номера (решение владельца 2026-11-12). |
| Одна обязательная галочка «согласен получать SMS» | Две отдельные необязательные, как на `/join` | Решение после юридической проверки (2026-11-02): согласие на заявки и на предложения Xtender — отдельно и добровольно. Без галочки о заявках профиль создаётся, но SMS о заявках не идут. |
| «Политика … и показ моего номера в каталоге» | Текст политики как на `/join` (там это уже сказано: «публичное размещение имени и номера в каталоге») | Одинаковый текст согласия на обоих путях регистрации. Как показывается номер — см. раздел 10. |
| — | Поле `provider_agreed: true` обязательно | Анкета хранится только после «да» мастера в переписке. |
| `profile_url` | Всегда `null` | Публичной страницы исполнителя нет. |
| Напоминание за 7 дней | Счётчик «за 14 дней» в админке | Прежнее правило владельца; SMS-текста о конце периода пока нет. |
| Новые направления на сайте | Шесть направлений заводятся один раз при выкладке (`outreachServicesSeed.js`) | Решение владельца 2026-11-12. Удалённая администратором категория не вернётся. |

## 13. Проверка «Готово, когда»

| Пункт ТЗ | Как проверено |
|---|---|
| Справочник, черновик, `confirm_url`, правка, статус, изменения, отказ | `tests/provider-drafts.test.js` через HTTP; демо |
| Повторный POST не создаёт дубль | там же |
| Зарегистрированный — `409 already_registered` | там же |
| `/c/{token}` на телефоне ka / ru / en, правки сохраняются, кнопка неактивна без галочек | тест + проход в браузере на 320 / 360 / 412 px |
| После подтверждения `confirmed`, профиль на модерации, согласие записано | тест (pg-mem и настоящий Postgres 18) |
| «Не интересно» стирает данные и вносит в список отказа | тест + браузер |
| Ключ передан владельцу и не попадает в код клиента или адрес | ключ выпускает сам владелец в админке; в адресе запрос отклоняется |

## 14. Демо

`node _demo-bot-drafts.js 3140` в рабочей копии (файл не в git): сайт в памяти, код всегда 1111, три анкеты
(ka / ru / en, английская — проба бота) созданы через API так же, как их создаёт бот; управляющая страница на
:3141 — ссылки, статусы, все SMS сайта, ключ API демо-копии. Админка — пароль `demo`. Новые направления (котлы,
газ, окна, электрика, кровля, покраска, плиточники) заведены только в демо.
