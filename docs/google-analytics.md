## 2. Где стоит метка и что уходит в Google

- **Только открытые страницы**: главная, `/join`, `/guides/request`, `/terms`, `/privacy` на трёх языках
  (`src/config/googleTag.js`, `PUBLIC_PAGE`). С 2026-10-09 к ним добавлены страницы под
  рекламу и поиск `/s/<slug>` ([landing-pages.md](landing-pages.md)): события формы на них те же. На страницах заявок, кабинетов, отзывов, в админке и
  кабинете менеджера Google нет: в их адресах секретные ссылки, а Google Analytics записывает адрес.
- **Адрес страницы** уходит только с рекламными метками (`utm_*`, `gad_*`, `gclid`, `gbraid`, `wbraid`,
  `dclid`, `srsltid`, `_gl`). Ссылка менеджера, промокод, ключ заявки отбрасываются. Переход со своей
  страницы передаётся как адрес сайта без пути.
- **Никогда не уходят**: телефон, текст заявки, номер заявки, исполнитель.
- **Не считаются**: браузеры сотрудников (метка `xt_staff` в localStorage, ставится в админке и кабинете
  менеджера) и роботы (`navigator.webdriver`).
- **Ремаркетинг и персонализация рекламы выключены в коде** (`allow_google_signals`,
  `allow_ad_personalization_signals` в `public/js/google-tag.js`): только статистика и конверсии.
- Идентификатор потока — `PRODUCTION_ID` в `src/config/googleTag.js`; переменная окружения
  `GA_MEASUREMENT_ID` его заменяет, пустая выключает. На локальной копии (dev-server) Google выключен,
  пока идентификатор не задан явно.

## 3. События

| Путь | Событие | Когда | Где в коде |
|---|---|---|---|
| Заявка | `lead_form_start` | первый символ в тексте заявки | `index.ejs` |
| | `lead_form_phone_step` | открыт шаг с телефоном | `index.ejs`, `goToPhoneStep` |
| | `lead_form_code_sent` | код отправлен | `index.ejs`, `sendOtp` |
| | **`generate_lead`** | заявка создана | `index.ejs`, `verifyOtp` |
| Каталог | `catalog_contact_start` | нажата кнопка номера или связи в карточке | `index.ejs` |
| | `catalog_code_sent` | код отправлен | `index.ejs`, `revealRequestCode` |
| | **`catalog_contact_open`** | номер исполнителя открыт впервые | `index.ejs`, `attemptReveal` |
| Регистрация исполнителя | `provider_signup_start` | пройден первый шаг | `join.ejs`, `nextSignupStep` |
| | `provider_signup_code_sent` | код отправлен | `join.ejs`, `sendOtp` |
| | **`sign_up`** | профиль создан | `join.ejs`, `verifyAndRegister` |

| Язык | `language_suggest_click` | нажата кнопка языка под шапкой: в подсказке «страница есть на вашем языке» или в выборе из трёх языков на английской версии страницы задачи; параметр `language` | `public/js/lang-suggest.js` (с 2026-10-09) |

Жирные — цели (ключевые события). Остальные — шаги воронки, целями их не делаем.

Форма одинаково размечена для компьютера и телефона: события привязаны к действиям (`goToPhoneStep`,
ответ сервера), а не к кнопкам, поэтому полноэкранный ввод на телефоне идёт через то же место.

## 4. Правила, о которые легко споткнуться

- **`catalog_contact_open` уходит только при первом открытии.** Один номер заказчика плюс один
  исполнитель дают одну цель, как и одно списание (`catalog_contact_access`). Повторное открытие того же
  исполнителя с того же номера событие не отправляет. При проверке брать исполнителя, которого с этого
  номера ещё не открывали.
- **Проверять только в окне инкогнито.** Обычный браузер владельца помечен как браузер сотрудника и не
  считается.
- **Шаги считаются один раз за открытие страницы**; `generate_lead` и `catalog_contact_open` — каждый раз.
- **Задержка.** Библиотека Google копит события до 5 секунд и отправляет пачкой; при уходе со страницы
  отправляет накопленное сразу. После `generate_lead` и `sign_up` человек уходит на страницу без Google,
  поэтому страница ждёт ответа библиотеки «событие принято» (несколько миллисекунд, не дольше 0,8 с).
  Заблокированная библиотека переход не задерживает.
- **Кнопка Google «Проверить работу тега»** может ответить «тег не найден»: метку подключает наш скрипт
  после загрузки страницы, роботам он её не показывает. Доказательство работы — «В реальном времени».
- **Технические заявки** (🧪, номер из «Настройки → Тестирование») в чужом браузере считаются конверсией:
  страница не знает, что номер тестовый.
- **Цифры в Google ниже настоящих**: блокировщики рекламы и сотрудники не считаются. Точное число
  заявок — в админке.
- **Новое событие** — без личных данных в параметрах; имя добавить в `tests/google-tag.test.js`.

## 5. Интерфейс Google Analytics (русский, октябрь 2026)

- Отчёт для проверки: «Отчёты → Обзор в режиме реального времени», карточка «Количество событий /
  Название события». В ней несколько страниц, листать стрелкой «>» внизу; строки с одинаковым числом
  между страницами пересортировываются.
- Цели: «Администратор → Просмотр данных → **События**». Вкладки «Ключевые события» и «Недавние
  события». Событие отмечается ключевым **звёздочкой** слева от названия на вкладке «Недавние события».
- Новые события появляются на вкладке «Недавние события» **в течение 24 часов**; 2026-10-08 она была пуста.
- Три строки на вкладке «Ключевые события» (`close_convert_lead`, `purchase`, `qualify_lead`) Google
  добавил сам; они пустые, не трогать.
- Кнопка «Создание события» → **«Создать без кода» не использовать**: она создаёт событие из просмотра
  страницы по условию на адрес, и цель считалась бы неверно.
- Связь с рекламой: «Администратор → Связь с другими продуктами → Связь с Google Рекламой».
- Срок хранения: «Администратор → Хранение данных».

## 7. План для Google Ads

1. Ключевые события: `generate_lead`, `catalog_contact_open`, `sign_up`.
2. Связать Google Analytics с Google Ads.
3. В Google Ads: «Цели → Конверсии → Создать действие-конверсию → Импорт → Ресурсы Google Аналитики 4 →
   Веб», отметить три события. Автоматическая пометка ссылок в Google Ads должна быть включена (так по
   умолчанию): по `gclid` Google связывает клик с заявкой.
4. Кампании на заказчиков: основная цель `generate_lead`, `catalog_contact_open` — второстепенная. Заявка
   уходит нескольким исполнителям и приносит больше, а открыть номер проще, и реклама начнёт гнаться за
   лёгким действием. Если заявок с рекламы меньше примерно 30 в месяц, автоматике не хватит данных —
   тогда сделать основными обе.
5. `sign_up` — только для кампаний по набору исполнителей.

Воронку по шагам собрать в «Исследования → Исследование воронки»: этапы — четыре события формы по порядку.

## 8. Приватность и открытые вопросы

- Политика конфиденциальности `v1.7-2026-10-08` называет Google Analytics в собираемых данных (2.2) и в
  получателях (2.6); см. [consent-and-legal.md](consent-and-legal.md). Грузинский текст без вычитки.
- Баннера согласия на куки нет: Грузия не входит в зону, где его требует Google; закон Грузии о
  персональных данных юрист по этому вопросу не смотрел.
- Ремаркетинг выключен. Чтобы собирать аудитории, убрать два флага в `public/js/google-tag.js`, поправить
  фразу в Политике и вернуться к вопросу о баннере.
- Повторное открытие номера целью не считается. Владельцу предложено изменить, если нужно; ответа нет.
