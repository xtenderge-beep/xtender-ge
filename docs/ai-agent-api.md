# API заявок для ИИ-ассистентов

Сделано 2026-10-19 по ТЗ, которое владелец получил от другой модели («AI-Native Procurement Infrastructure & RFQ API»).
ТЗ просило отдельный сервис на Python/FastAPI, где заявка сразу становится активной. Владелец выбрал другой вариант
(вопрос и ответ 2026-10-19): API встроено в нынешний сайт, и номер подтверждается кодом из SMS. Отличия от ТЗ
перечислены в разделе 5.

В тот же день пришла вторая версия ТЗ («Stateful GET-Handoff», текст — [ARCHITECTURE_SPEC.md](../ARCHITECTURE_SPEC.md)):
ассистент не вызывает API, а даёт человеку ссылку `/draft?…` с уже заполненной заявкой. Сделано так же, в нынешнем
сайте, — раздел 8. Ссылка — главный путь: её может дать любой ассистент в обычном чате, API нужен только своему GPT
с действием.

## 1. Зачем

Человек пишет ассистенту («нужна арматура d12, 2 тонны, Сабуртало»), и ассистент оформляет заявку на xtender.ge от
его имени. Дальше заявка идёт обычным путём: модератор, рассылка, звонки исполнителей.

Сам по себе ассистент API не вызывает, даже если прочитал `llms.txt`. Для этого нужен плагин ChatGPT или коннектор
Claude (оба на MCP; его нет). Свой GPT с действием больше не вариант: OpenAI закрывает их, см. раздел 4.

## 2. Как идёт заявка

1. Ассистент показывает человеку ссылки на Оферту и Политику и спрашивает, согласен ли он передать номер и заявку
   подходящим исполнителям.
2. `POST /v1/rfq/create`: сайт создаёт черновик (статус `unverified`, как у формы на сайте) и отправляет код по SMS.
   В ответе `rfq_id` (это `orders.token`) и `challenge_id`.
3. Человек называет код ассистенту. `POST /v1/rfq/<rfq_id>/verify` с `code` и `challenge_id`: заявка подтверждена
   (`pending_review`). Дальше то же, что у формы: вторая SMS со ссылкой на заявку, перевод текста, сообщение модератору,
   карточка «Кратко».
4. Ассистент даёт человеку `tracking_url`, то есть его страницу `/o/<owner_token>`: статус и закрытие заявки.

Без кода заявка никому не уходит, иначе любой мог бы вписать чужой номер. SMS с кодом своя:
«Xtender code: 1234. Give it to your AI assistant to send your request. Not you? Ignore this SMS.» Строки
автоподстановки кода в ней нет: человек не на сайте.

## 3. Адреса

| Адрес | Что |
|---|---|
| `POST /v1/rfq/create` | Обязательные поля: `category`, `items` (`[{name, quantity}]`, от 1 до 30), `district`, `customer_phone` (грузинский номер в любом написании, сохраняется как `+995…`), `terms_accepted: true`, `privacy_accepted: true`. Необязательные: `details`, `city`, `customer_name`, `language` (`ka`/`ru`/`en`, по умолчанию `en`, язык страницы заявки), `rfq_id` (новый код для того же черновика) |
| `POST /v1/rfq/:rfq_id/verify` | `code` (4 цифры), `challenge_id` |
| `GET /openapi.json` | Описание для моделей (OpenAPI 3.1, `operationId`: `createRequest`, `verifyRequest`) |
| `GET /llms.txt` | Текст для моделей по образцу llmstxt.org: как собрать ссылку `/draft`, коды услуг с исполнителями, затем API |
| `GET /draft?…` | Ссылка-черновик: готовая заявка с кнопкой «Подтвердить», раздел 8 |
| `POST /mcp` | MCP-сервер для плагина ChatGPT и коннектора Claude, раздел 10 |

Статусы в ответах: `PENDING_VERIFICATION` (ждёт кода), `IN_REVIEW` (у модератора). Ошибки:
`{success: false, error, message, field?}`. Коды ошибок: `invalid_request`, `consent_required`, `rate_limited`,
`sms_failed`, `not_found`, `invalid_code`, `already_confirmed`, `code_for_other_request`.

Текст заявки собирается так: первая строка — `category`, дальше по строке на каждую позицию («- Арматура d12 — 2
тонны»), затем `details` и «Имя: …» на языке `language`. `district` и `city` пишутся в `orders.district_name` через
запятую. Город (`city_id`) по-прежнему ставит модератор. Проверка «бессмыслицы» простая: в категории и в каждой позиции
должно быть хотя бы две буквы.

Ограничения: 3 кода в час на номер (общие с формой, `otp.service`), 30 запросов кода в час с одного IP. Запросы GPT
приходят с серверов OpenAI, у многих людей один IP: если в это упрёмся, лимит надо поднять (`IP_LIMIT_PER_HOUR`).

Список услуг в `llms.txt` и в описании поля `category` берётся из каталога: только услуги и города, где сейчас есть
исполнители (как страницы «услуга + город»). Он кешируется на 10 минут.

## 4. Как попасть в магазины ассистентов (решает владелец)

**Свой GPT больше не делать.** Поиск 2026-10-19 (справка OpenAI по адресу не открылась, 403; даты — по нескольким
пересказам объявления от 2026-09-11): OpenAI закрывает свои GPT 11 декабря 2026 и переводит их в «плагины»; действия
(Actions из `/openapi.json`) сами не переносятся, их надо переделывать через MCP-сервер. С июля 2026 приложения ChatGPT
называются плагинами; их делают на Apps SDK (основа — MCP), подают на проверку через платформу разработчика OpenAI,
нужна политика конфиденциальности.

Что есть у площадок на 2026-10-19:

| Площадка | Как | Что нужно от нас |
|---|---|---|
| ChatGPT | Плагин (приложение) в каталоге, после проверки OpenAI | MCP-сервер на сайте, аккаунт разработчика владельца |
| Claude | Коннектор в каталоге Connectors Directory, после проверки Anthropic (форма заявки) | Тот же MCP-сервер, удалённый (по адресу в интернете) |
| Gemini | Публичного каталога «Gems» нет; Gem можно отдать по ссылке, как файл в Google Drive | Только текст инструкции; внешние адреса Gem не вызывает, ссылку Gemini пропускает через поиск (тест выше) |

Один MCP-сервер на сайте (например, `https://xtender.ge/mcp`) годится и для ChatGPT, и для Claude: инструменты
«услуги с исполнителями» и «собрать ссылку на заявку» (или заявка с кодом из SMS, как `/v1/rfq`). Не сделано: ждёт
решения владельца.

Прежний текст раздела (свой GPT с действием из `/openapi.json`) устарел по причине выше. `/openapi.json` и `/v1/rfq/*`
остаются: их можно вызывать из MCP-сервера или любого другого клиента.

## 5. Что сделано не так, как в ТЗ

| ТЗ | Сделано | Почему |
|---|---|---|
| Отдельный сервис на Python/FastAPI, своя база | Те же адреса в нынешнем сайте (Node.js) | Иначе заявка лежала бы в отдельной таблице и не дошла бы до модератора и исполнителей |
| Заявка сразу `ACTIVE` | Сначала код из SMS, затем модератор | Чужой номер; на сайте каждая заявка подтверждается кодом |
| Таблица `ComplianceLog` | Существующий журнал `sms_consent_logs` (только запись, триггер на проде) | Он уже хранит IP, браузер, время, номер и текст согласия |
| `RFQ_CREATED` | `ORDER_REQUESTED_VIA_API` (канал `api`, всё, что прислал ассистент), затем обычные `SMS_OTP_SENT`, `CLIENT_CONSENT_OTP_VERIFIED`, `ORDER_PUBLISHED`, `ORDER_DETAILS_RECORDED` | |
| `tracking_url` вида `/t/<uuid>` | `/o/<owner_token>`, та же страница, что по ссылке из SMS | |
| `auto_close_at` через 72 часа | Не сделано | На сайте заявки сами не закрываются; это отдельное решение для всех заявок |
| `source_url` — где нашли поставщика; `CLICK_OFFER_ACCEPTED`, `OPT_OUT_REQUESTED` | Не сделано | Это про рассылку людям с сайтов объявлений, которые у нас не регистрировались. Сначала нужен ответ юриста, см. раздел 6 |
| Настраиваемый CORS | Не менялся | На сайте уже `cors()` для всех адресов; GPT ходит с сервера, CORS ему не нужен |
| Dockerfile | Не нужен | Сайт уже выкладывается на Railway |

## 6. Открытые вопросы

- **Согласие со слов ассистента.** Галочек человек не ставит: о согласии сообщает ассистент (`terms_accepted`,
  `privacy_accepted`), а человек подтверждает заявку кодом. В журнале снимок согласия помечен
  `acceptance_method: 'ai_agent_reported'`. Достаточно ли этого, — вопрос юристу вместе с Офертой.
- **Стройматериалы.** В примерах ТЗ арматура и бетон, но услуги «Стройматериалы» и магазинов в базе пока нет: такую
  заявку модератору некому отправить.
- **Следующий модуль ТЗ** (рассылка SMS/WhatsApp поставщикам с сайтов объявлений). Писать людям, которые не
  регистрировались, — вопрос к юристу по закону Грузии о персональных данных. Журнал записей согласие не заменяет.
  Сейчас заявки получают только зарегистрированные исполнители (две галочки и код).

## 8. Ссылка-черновик `/draft` (вторая версия ТЗ)

Сделано 2026-10-19. Текст ТЗ — [ARCHITECTURE_SPEC.md](../ARCHITECTURE_SPEC.md) (модули 1 и 2 из четырёх).

### Как идёт заявка

1. Ассистент читает `/llms.txt`, помогает человеку описать задачу и даёт ссылку:
   `https://xtender.ge/draft?lang=ru&cats=movers,van&loc=Сабуртало&title=…&items=Диван:1:шт;Холодильник:1:шт&note=…`
2. Ссылка открывает главную того же вида, что страницы услуг. Текст задачи уже в поле:
   ```
   Переезд из Ваке
   - Диван — 1 шт
   - Холодильник — 1 шт
   Завтра после 18:00, 3 этаж, без лифта
   Место: Сабуртало
   ```
   Над полем пояснение: «Текст задачи подготовил ИИ-ассистент. Проверьте его и поправьте, если нужно. Пока вы не
   подтвердите номер кодом из SMS, задачу никто не увидит.» Ниже строка с живыми числами каталога: «Исполнители
   в Тбилиси: Грузчики — 3, Перевозки — 1». Услуги из `cats` в каталоге первыми, их хэштег нажат.
3. Дальше обычная форма: номер, две галочки согласия, код из SMS, модератор. Согласие человек даёт сам, на сайте,
   поэтому вопроса «согласие со слов ассистента» (раздел 6) у ссылки нет.

До нажатия кнопки ничего не сохраняется. Источник заявки — «ИИ-ассистент (ссылка)» (`orders.source`), у модератора
в Telegram строка «🤖 Текст подготовил ИИ-ассистент (ссылка), заказчик проверил его на сайте».

### Параметры

| Параметр | Что | Предел |
|---|---|---|
| `lang` | `ka`, `ru`, `en`. Без него язык по письменности текста. Язык в адресе (`/ru/draft`) важнее | |
| `title` | Задача в нескольких словах | 120 знаков |
| `items` | `название:количество:единица` через `;`. Количество и единица необязательны | 30 позиций, название 200 знаков |
| `loc` | Район или город. `saburtalo` показывается как «Saburtalo». Если это город из базы (по адресу или названию), каталог открывается на нём | 80 знаков |
| `note` | Остальное, можно в несколько строк | 1000 знаков |
| `cats` | Коды услуг (`service_categories.slug`) через запятую. Неизвестные и выключенные отбрасываются | 10 кодов |

Без `title`, `items` и `note` ссылка ведёт на главную. Страница закрыта от поиска (`noindex`), карточка в мессенджере
строится по задаче («Задача: Переезд из Ваке» и позиции), `canonical` — полный адрес с параметрами. Переключатель
языка уносит параметры с собой, подсказка «есть версия на вашем языке» на этой странице выключена: она вела бы на
пустой `/draft`.

### Что сделано не так, как в ТЗ

| ТЗ | Сделано | Почему |
|---|---|---|
| При открытии ссылки черновик сохраняется в `rfqs`, адрес заменяется коротким `/draft/x89k2` | Не сохраняется, адрес остаётся длинным | Ссылку открывают роботы мессенджеров, когда строят карточку: каждая пересылка создавала бы черновик. Длинная ссылка при пересылке не ломается, она та же |
| Числовые ID категорий `101,102` | Коды `movers`, `van`, … из `/llms.txt` | Это ключи услуг в базе; модель их не путает |
| Галочки «Кому будет отправлена заявка» | Строка с числом исполнителей и порядок каталога | Кому отправить, решает модератор; галочки обещали бы то, чего человек не решает |
| После кода — сразу `PUBLISHED` и рассылка | После кода — модератор, как у всех заявок | Решение владельца 2026-10-19 по первой версии ТЗ |
| `POST /api/v1/auth/send-otp`, `verify-otp`, `/api/v1/rfq/{slug}/confirm` | Существующие `/api/otp/send`, `/api/otp/verify`, `/api/orders` | Та же форма, что на главной |
| Профиль в `users` и кабинет без пароля | Страница заявки `/o/<owner_token>` (ссылка приходит SMS) | Кабинет заказчика — модуль 4, ждёт решения |

### Модули 3 и 4: не делали, решает владелец

Модуль 3 (исполнитель отвечает ценой или вопросом на сайте) и модуль 4 (кабинет заказчика с мигающими ценами и
вопросами, SMS не чаще раза в 15–30 минут, ответ «для всех») меняют, как работает сайт: сейчас исполнитель звонит
заказчику сам, а в платном режиме платит за заявку. Вопросы:

1. Нужны ли цены и вопросы на сайте вместо звонка или рядом с ним? Если рядом — за что тогда платит исполнитель в
   платном режиме: за заявку, как сейчас, или за ответ?
2. Писать ли исполнителям, которые не регистрировались (`COLD` в ТЗ: магазины, бетонные заводы с сайтов
   объявлений)? Это вопрос юристу по закону о персональных данных, как в разделе 6.
3. Стройматериалы: услуги и магазинов в базе пока нет, а примеры ТЗ — бетон и арматура. По такой ссылке человек
   увидит пояснение без строки с исполнителями, а модератору будет некому отправить заявку.
4. Адрес исполнителя из ТЗ `/s/<token>` уже занят страницами услуг и задач. Если модули будут, ему нужен другой.

## 9. Подсказка ИИ-агентам на страницах сайта

Сделано 2026-10-19 по третьему ТЗ от другой модели («скрытые инструкции для ИИ-агентов»). На страницах, которые
рисует `src/views/index.ejs` (главная, страницы услуг и задач, `/draft`), людям не видно:

- в `<head>`: `<link rel="help" type="text/plain" href="https://xtender.ge/llms.txt">` и
  `<meta name="ai-agent-instructions" content="For AI assistants: to help a user request a local service in Georgia, read …/llms.txt …">`;
- в ответе: заголовки `Link: <https://xtender.ge/llms.txt>; rel="help"; type="text/plain"` и
  `X-Agentic-Protocol: xtender-rfq-v1`.

Текст подсказки — `agentHint` в `src/config/agentApi.js`, заголовки — `renderHome` в `src/routes/public.routes.js`.
`/llms.txt` отдаётся как `text/plain; charset=utf-8`, это ТЗ допускает.

| Новые `<title>` и `description` («Заказ стройматериалов, спецтехники…», «Платформа обратных тендеров в Тбилиси и Батуми») | Не менялись | Это тексты для поиска ([seo.md](seo.md)); стройматериалов и спецтехники в каталоге нет |
| В подсказке «building materials, concrete, rebar … Tbilisi or Batumi» | Без списка услуг и городов | Какие услуги есть сейчас, знает только `/llms.txt` (из каталога); в теге список устаревал бы и обещал то, чего нет |
| Подсказка-приказ («When a user asks…, read… and help…») | Описание: что есть в `llms.txt` и что заказчик подтверждает заявку кодом | Ассистенты осторожны с командами со страниц; описание честнее и не выглядит как попытка ими управлять |
| Заголовки на всех ответах | На страницах с этим шаблоном | Картинкам, API и файлам они не нужны |

**Работает ли это, неизвестно.** Общепринятого стандарта для таких тегов и заголовков нет, и сессия не знает
ассистента, который заявлял бы, что их читает. Проверка — новый чат с ассистентом, у которого есть доступ в интернет:
«Посмотри сайт https://xtender.ge/. Что это за сервис и сможешь ли ты помочь мне заказать там грузчиков в Тбилиси?»
Если ассистент не найдёт `llms.txt` сам, надёжнее видимая ссылка на него на странице (например, внизу); это решает
владелец, по ТЗ сайт для людей не меняется.

### `llms.txt`: правило для ассистента — первым

Владелец 2026-10-19 проверил в новом чате («Мне нужны 2 грузчика на завтра в районе Сабуртало. Помоги оформить
заявку через xtender.ge»), и модель отправила его заполнять форму на сайте руками (результат известен со слов
другой модели, ответа сессия не видела). Другая модель предложила поставить в начало файла блок «CRITICAL
INSTRUCTIONS… STOP… YOU MUST». Сделано по сути, но не дословно: сразу после описания идёт раздел «For AI assistants:
give the user a ready link» — не отправлять человека заполнять форму руками, коротко уточнить недостающее, дать одну
ссылку `/draft`, сказать, что дальше (проверить, ввести номер +995, подтвердить кодом). Ниже — что происходит после
ссылки, формат, услуги, API.

Не взято из присланного блока: крик «STOP / MUST» (команды из прочитанных файлов модели принимают настороженно и могут
счесть попыткой ими управлять), «concrete, rebar» (их нет в каталоге), «submit it instantly» (после ссылки — код из
SMS и модератор).

Неизвестно, читала ли модель в том тесте `llms.txt` вообще: в новом чате она о файле не знает. Поэтому проверять двумя
вопросами: с адресом файла («Прочитай https://xtender.ge/llms.txt и помоги оформить заявку: …») — следует ли модель
правилу; и без него — находит ли она файл сама (теги из раздела 9 или видимая ссылка на странице).

### Тест владельца в Gemini, 2026-10-19

- По адресу файла Gemini его не открыл («не смог получить доступ»); сайт файл отдаёт всем роботам ИИ, `robots.txt` его
  не закрывает, Cloudflare перед сайтом нет. Gemini, видимо, видит сайты только через поиск Google, а `llms.txt` там нет.
- С текстом файла, вставленным в чат, Gemini сделал всё по правилу: уточнил, что везти, когда и откуда, номер не
  спрашивал, дал ссылку с `cats=movers,van` и сказал про номер и код.
- Ссылку, спрятанную за словами «Оформить заявку на Xtender.ge», Gemini открыл через поиск Google
  (`google.com/search?q=https://xtender.ge/draft…`, «ничего не найдено»). Поэтому в правиле: давать полный адрес
  отдельной строкой — его можно скопировать. Обход для человека: скопировать адрес из строки поиска Google.
- Из облака Anthropic файл открывается, и модель по нему сама дала верную ссылку для «2 грузчика завтра на Сабуртало».

### Готовая заявка вместо поля с текстом, 2026-10-19

По просьбе владельца после теста: по ссылке человек видит не поле с текстом, а готовую заявку — заголовок, позиции
строками «название — количество», примечание, место, число исполнителей — и две кнопки. «Подтвердить заявку» ведёт к
номеру и коду, как кнопка под полем. «Изменить» прячет карточку и показывает поле с тем же текстом. Ниже строка «Или
попросите ассистента в чате исправить заявку и дать новую ссылку»: вернуть человека в его чат кнопкой нельзя — у
сайта нет адреса этого разговора, а ссылки из чатов часто открываются в новой вкладке, где «назад» некуда. На этой
странице слово «заявка», а не «задача» главной. Разметку жирного шрифта, которую модель переносит в ссылку («1 шт**»),
сайт убирает.

### Тест владельца в «Режиме ИИ» Google, 2026-10-19

Вопрос без адреса файла: «Посмотри сайт xtender.ge и помоги заказать 2 грузчиков на завтра в Сабуртало». Ответ:
заполнить форму на главной (кнопки названы приблизительно) или позвонить исполнителям из каталога (назвал троих
настоящих); ссылки `/draft` нет. Это не отказ от правила: «Режим ИИ» отвечает по индексу Google, `llms.txt` не читает
(справка Google, [seo.md](seo.md), раздел 2: «You don't need to create new machine readable files, AI text files, or
markup»), а строку внизу главной Google ещё не видел — её выложили за час до теста. Ссылку, собранную самим ИИ, сервисы
Google, судя по тесту в Gemini, пропускают через поиск. Вывод: путь «ИИ даёт ссылку» — для ChatGPT и Claude; от Google
ждать ответа «заполните форму на сайте или позвоните из каталога», и он людей на сайт и приводит.

xtender.ge/llms.txt» (ka: «AI-ასისტენტებისთვის:», en: «For AI assistants:»). Адрес написан текстом: ассистент,

### Блок «For AI assistants» внизу страниц, 2026-10-19

По просьбе владельца: ассистент, открывший главную, сразу видит, как помочь человеку, — без перехода в `llms.txt`.
Внизу главной и страниц услуг, под подвалом, мелким текстом по-английски (`lang="en"`): собрать заявку у себя в чате и
дать ссылку полным адресом; зачем так человеку (формы нет, подробности ассистент уже знает, заявка приходит полной,
человеку остаётся проверить, нажать «Подтвердить» и ввести код); формат ссылки; коды услуг с исполнителями (живые, из
`assistantCatalog`); что дальше и как человеку решать (модератор, исполнители звонят или пишут, человек сравнивает,
договаривается сам и закрывает заявку по ссылке из SMS; для заказчика бесплатно); ссылка на полный `llms.txt`.

Блок **видимый, не скрытый**: скрытый текст для роботов Google считает спамом ([seo.md](seo.md)). Тон — объяснение
пользы, без приказов. Те же тексты «зачем» и «что дальше» (`WHY`, `AFTER` в `agentApi.js`) — в `llms.txt` и в
инструкции MCP-сервера. Проверено на `dev-server`: 320, 390 и 1280 px без сдвига вбок.

## 10. MCP-сервер `/mcp`

Сделано 2026-10-19 по решению владельца (раздел 4): основа для плагина ChatGPT и коннектора Claude. С ним ассистенту
не нужно искать `llms.txt`: правила и список услуг он получает от сервера, как только человек подключил xtender.

- Адрес: `POST https://xtender.ge/mcp`, Streamable HTTP, без входа и без состояния (на каждый запрос свой сервер,
  ответ — JSON). `GET` и `DELETE` — 405. Библиотека — официальная `@modelcontextprotocol/sdk` 1.32.1 и `zod` 3.25.76.
- Инструкция сервера (`instructions`) — то же правило, что в начале `llms.txt`: уточнить недостающее, вызвать
  `create_request_link`, дать ссылку полным адресом, номер в чате не спрашивать, цену и сроки не обещать.
- `list_services` — услуги с исполнителями по городам: код, названия на трёх языках, число исполнителей.
- `create_request_link` — поля `lang` (обязательно), `title`, `items` (`name`, `quantity`, `unit`), `location`, `note`,
  `services` (коды). Возвращает ссылку `/draft`, текст заявки, как он будет на странице, и предупреждения: код без
  исполнителей выброшен; ни одной услуги с исполнителями нет. Двоеточие и точку с запятой в позициях заменяет
  пробелом, чтобы не сломать разбор ссылки.
- Оба инструмента помечены «только чтение» (`readOnlyHint: true`, `destructiveHint: false`): сервер ничего не пишет в
  базу и номер телефона не принимает. Заявку человек подтверждает на сайте кодом из SMS, как по любой ссылке.
- Каталог услуг — общий с `/llms.txt` и `/openapi.json`: `src/services/assistantCatalog.service.js`, 10 минут в памяти.

Проверено: `node tests/mcp.test.js` — подключение клиентом из той же библиотеки, инструкция, оба инструмента,
ссылка открывает на сайте ту же заявку, в базе ничего не появилось; на `dev-server` — запросы без библиотеки
(версии протокола `2025-06-18` и `2025-03-26`, уведомление — 202, неверный JSON — ошибка `-32700`, неизвестный метод —
`-32601`), грузинский текст.
