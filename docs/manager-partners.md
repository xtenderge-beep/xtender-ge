# Партнёрская программа менеджеров

Реализация: 13.09.2026. Начальная ставка — **25%**. Администратор меняет её
индивидуально в карточке менеджера (0–100%, точность 0,01 процентного пункта).

## Работа администратора

1. `/admin/managers` → добавить менеджера или открыть существующего.
2. Блок «Партнёрская программа» → «Создать реферальную ссылку специалиста».
3. Скопировать нужный языковой вариант постоянной ссылки (`/p/<id>-<token8>?lang=ka|ru|en`
   → редиректит на `/join?ref=<token>` в соответствующей локали, 2026-09-17, см.
   `public.routes.js`) и передать менеджеру. Менеджер может обойтись и без админки —
   все 3 варианта видны у него в кабинете `/manager` и по команде `/link` (без номера)
   боту в Telegram.
4. Здесь же настроить процент. Старые комиссии сохраняют исходную ставку.
5. `/admin/partner-payouts` → выбрать месяц → открыть менеджера.
6. После реального перевода денег указать сумму и банковское подтверждение.
   Кнопка регистрирует перевод, не отправляет деньги.

Отчёт показывает пополнения, число операций, начисления, записанные выплаты,
остаток месяца и непогашенный остаток прошлых месяцев. В деталях — специалист,
операция пополнения, база, ставка, комиссия; история выплат и список привлечённых.
Старый долг гасится записью выплаты в соответствующем месяце начисления.
Частичные выплаты поддерживаются. Ошибочную запись можно отменить с причиной;
банковский перевод при этом не возвращается.

## Что видит получатель ссылки

С 2026-09-21 (commit `4e85bf7`) получатель реферальной или промо-ссылки видит страницу
`/join` без рекламной части: заголовок «Регистрация исполнителя», форму и, если в ссылке
промокод, одну строку с суммой. Блоки про бонус, тарифы и инструкцию скрыты, они есть в
кабинете после регистрации. Полная страница остаётся для тех, кто пришёл без ссылки.
Режим сохраняется, пока в браузере есть cookie реферала, и не пропадает при смене языка.
Правила и тест: [copy-and-cognitive-load.md](copy-and-cognitive-load.md).

## Привязка

- Первый действительный реферальный переход сохраняется в httpOnly-cookie
  на 30 дней. Другой действительный переход не заменяет уже сохранённый источник.
- Только новая регистрация закрепляет `masters.referral_manager_id`.
  Повторная регистрация существующего телефона не позволяет сменить источник.
- При отсутствии действительной реферальной ссылки новый специалист может
  получить источник из действительного менеджерского промокода прежней системы.
- `manager_id` остаётся текущим ответственным, а `referral_manager_id` — источником
  для комиссии. Изменение ответственного не переносит комиссию автоматически.
  Автоматическое правило передачи комиссий новому менеджеру не реализовано.
- Для прежней базы нет автоматической миграции источников: администратор может
  закрепить специалиста без источника через карточку менеджера, указав ID
  и основание. Повторное закрепление запрещено; старые пополнения не пересчитываются.
- Отключённый менеджер не получает новые реферальные регистрации, но комиссия
  по ранее закреплённым сохраняется. Для остановки будущих начислений используется 0%.

## База и расчёт

Комиссия создаётся только для положительной операции `reason='topup'` при наличии
закреплённого источника. Подтверждением денег в этой модели является запись
пополнения администратором/модератором; загрузка чека сама по себе не начисляет
ни баланс, ни комиссию. `promo`, `admin_correction`, списания и неположительные
суммы исключены. Если денежный перевод записан как admin_correction, комиссия
не появится — используйте штатное пополнение для денежных поступлений.

Формула в целых числах: `round(base_tetri × rate_bps / 10000)`.
Ставка 2500 bps = 25%; половина тетри округляется вверх. В каждой комиссии
сохраняются база и ставка на момент операции, менеджер, специалист и ID пополнения.

Начисление не уменьшает баланс специалиста. Это отдельное обязательство платформы
перед менеджером. Изменение ставки не пересчитывает старые обязательства.
Нет автоматического начисления задним числом за операции до внедрения/привязки.

Месяцы — календарные по Тбилиси. Выплата относится к месяцу начисления,
а время записи выплаты хранится отдельно. Исторический отчёт учитывает все
записанные к моменту просмотра выплаты за этот месяц, включая более поздние;
это текущий расчёт долга за месяц, не бухгалтерский снимок на его последний день.

## Целостность

- Пополнение, журнал баланса и комиссия записываются в одной транзакции.
  Ошибка комиссии откатывает всю операцию пополнения.
- Уникальный transaction_id исключает повторную комиссию с одной операции.
- Блокировка строки менеджера сериализует начисление, изменение ставки и выплаты.
- Уникальный request_key защищает повторный запрос выплаты; превышение остатка
  месяца запрещено. Это не автоматическая банковская сверка номера перевода.
- Формы доступны только администратору с CSRF. Менеджер не меняет собственный процент.
- Создание ссылки, смена процента, привязка, запись и отмена выплаты оставляют
  записи в partner_audit. В UI журнала редактирования нет; административный
  доступ напрямую к БД этой реализацией не ограничивается.

## Файлы и таблицы

- `src/services/partner.service.js` — ссылки, привязка, ставки, начисления, выплаты.
- `src/controllers/partner.controller.js`, `src/routes/admin.routes.js` — админка.
- `src/services/master.service.js` — регистрация и атомарное начисление с topup.
- `src/routes/public.routes.js`, `src/controllers/master.controller.js` — реферальный переход.
- `src/views/admin/_partner-settings.ejs`, `partner-payouts.ejs`, `src/views/manager/dashboard.ejs` —
  интерфейс (3-языковые варианты ссылки, 2026-09-17).
- `src/controllers/order.controller.js` `handleManagerCommand` — бот, `/link` (без номера).
- `schema.sql`: поля managers/masters; manager_commissions, manager_payouts, partner_audit.

Схема добавочная и идемпотентная. Миграция не делает реальных выплат, не меняет
существующие балансы и не создаёт комиссий за прежние пополнения.

## Проверки и границы

`node tests/partners.test.js`: 25%, изменение ставки, повторные пополнения,
округление, нулевая ставка, исключение бонусов, неизменность источника,
переходы по ссылкам и локали, повторные выплаты, частичные выплаты/отмена,
переплата, перенос долга, ручная привязка, откат транзакции, HTTP/CSRF и EJS.
Существующие dashboard/consent/topups/welcome-bonus/language-switch/master-session
также проверяются. Тесты на pg-mem не доказывают поведение конкурирующих
транзакций реального PostgreSQL.

Автоматические банковские переводы, возврат комиссии при возврате реальных
денег, произвольные корректировки комиссий, налоговые документы менеджеру
и кабинет менеджера с доступом к этому отчёту пока не реализованы.
При реальном возврате или ошибочном денежном пополнении требуется отдельный
процесс корректировки обязательств: обычный admin_correction этого не делает.
