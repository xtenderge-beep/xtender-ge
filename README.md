# Xtender

Сервис-маркетплейс для заказа услуг по районам Тбилиси: перевозки/машины, грузчики, вывоз мусора. Клиент публикует заявку текстом, модератор вручную распределяет её по категориям исполнителей через Telegram, исполнители получают SMS со ссылкой на заявку.

Прод: **https://xtender.ge**

## Как это работает

1. Клиент на главной странице описывает задачу текстом и жмёт «Опубликовать».
2. Указывает телефон → получает SMS с 4-значным кодом и короткой ссылкой на свою заявку (`/o/<owner_token>`).
3. Вводит код → заявка подтверждается и уходит **модератору в Telegram-бот** с кнопками категорий (Машины/Грузчики/Вывоз мусора/Бортовые, машины дополнительно по размеру L/XL/XXL).
4. Модератор нажимает нужные категории (можно несколько) → активным мастерам этой категории уходит SMS со ссылкой на заявку (`/order/<token>`) → сообщение модератора в Telegram обновляется на месте: статус, кто получил рассылку, воронка кликов.
5. Мастер открывает ссылку → видит заявку → «Позвонить» / WhatsApp — клики логируются и обновляют воронку в Telegram-сообщении.
6. Клиент в любой момент может открыть свою ссылку (`/o/...`, работает без кук/с любого устройства) и закрыть заявку — сообщение в Telegram обновится на «🔒 закрыта», новые мастера по старым ссылкам увидят, что заявка уже занята.

Отдельно есть каталог исполнителей на главной странице (фильтр по категории/размеру) — клиент может звонить напрямую в обход модерации.

### Регистрация исполнителей и баланс

Исполнители регистрируются сами на `/join` (форма на 3 языках, с OTP-подтверждением телефона — как у клиента, но отдельным Redis-неймспейсом, см. `otp.service.js`). Новый мастер создаётся с `is_active = false` и уходит модератору в Telegram с кнопкой «✅ Одобрить» — только после этого он появляется в каталоге и в рассылке.

Модель оплаты — за лид: каждое SMS-уведомление о заявке стоит **30 тетри**, списывается с баланса мастера (`masters.balance_tetri`, в тетри — 1 GEL = 100 тетри). Если баланса не хватает — мастера просто пропускают при рассылке (без ухода в минус). Пополнение баланса — вручную: исполнитель переводит деньги (минимум 5 GEL) по договорённости, модератор подтверждает командой прямо в Telegram-боте:

```
/topup +995599112233 10
```
(номер телефона + сумма в GEL — зачислится на баланс этого мастера). Никакого онлайн-эквайринга нет.

Сразу после регистрации исполнитель получает SMS с личной ссылкой `/master/<master_token>` (без пароля, по аналогии с `/o/<owner_token>` у клиента) — там в любой момент видно статус (на модерации / активен) и текущий баланс.

## Стек

- Node.js + Express 4, шаблоны — EJS (`src/views`)
- PostgreSQL (`pg`) — основное хранилище
- Redis (`ioredis`) — OTP-коды, лимиты по частоте отправки
- Telegram Bot API — модерация заявок (обычные HTTP-запросы через `axios`, без SDK)
- Свой SMS-шлюз (HTTP GET) — код подтверждения и рассылка мастерам
- Multer — загрузка фото/PDF к заявке
- Railway — хостинг и автодеплой, Cloudflare — домен

## Локальная разработка

```
node dev-server.js
```

Поднимает сервер на `localhost:3000` с **in-memory** Postgres (`pg-mem`) и Redis (`ioredis-mock`) — реальная БД не нужна, SMS не отправляются (пишутся в консоль). Автоматически сеет 50 демо-мастеров при старте.

**Никогда не запускайте `npm start` / `node src/app.js` локально** — `.env` содержит настоящие продовые ключи (SMS-шлюз, Telegram-бот), реальные SMS могут уйти по реальным номерам, а приложение подключится к продовой базе.

Известные ограничения `pg-mem` (если правите SQL-миграции — проверяйте на реальной Postgres тоже):
- не поддерживает `ANY($1::uuid[])` на UUID-массивах
- не поддерживает коррелированные подзапросы
- `ON CONFLICT DO NOTHING RETURNING *` возвращает существующую строку вместо пустой
- падает при повторном прогоне DDL через `Pool.query()` на некоторых constraint'ах — поэтому `dev-server.js` выставляет `SKIP_DB_MIGRATIONS=1` и накатывает схему сам через нативный API `pg-mem`

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт сервера (Railway подставляет сам) |
| `DATABASE_URL` | строка подключения к Postgres |
| `REDIS_URL` | строка подключения к Redis |
| `DOMAIN` | домен без протокола (`xtender.ge`) — используется для сборки ссылок в SMS и Telegram-сообщениях (`src/config/url.js`). Без неё ссылки падают на `http://localhost:3000` |
| `SMS_GATEWAY_URL` | адрес SMS-шлюза (необязательно, есть дефолт в коде) |
| `SMS_GATEWAY_USERNAME` | логин SMS-шлюза |
| `SMS_GATEWAY_PASSWORD` | пароль SMS-шлюза |
| `TELEGRAM_BOT_TOKEN` | токен бота-модератора (`@xtendergebot`) |
| `TELEGRAM_MODERATOR_CHAT_ID` | chat_id, куда шлются заявки на модерацию |
| `NODE_ENV` | `development` включает dev-режимы (SMS/Telegram не отправляются по-настоящему) |
| `SKIP_DB_MIGRATIONS` | пропустить авто-накат `schema.sql` при старте (нужно только `dev-server.js`) |

Полный список с пустыми значениями — в `.env.example`.

## База данных

Схема живёт в одном файле `schema.sql` и накатывается автоматически при каждом запуске (`runMigrations()` в `app.js`), включая прод — миграции идемпотентны (`CREATE TABLE IF NOT EXISTS` + отдельные `ALTER TABLE ADD COLUMN IF NOT EXISTS` для полей, добавленных позже).

Основные таблицы:
- **masters** — каталог исполнителей: категория, тип/размер машины, цена, телефон, активность, подписка, `balance_tetri` (баланс в тетри)
- **orders** — заявки: описание, район, статус (`unverified` → `pending_review` → `closed`), `token` (для мастеров) и `owner_token` (для клиента) — два независимых коротких (10 символов) идентификатора, чтобы мастер не мог подделать доступ владельца
- **order_dispatches** — какой категории (и размера) уже отправлена рассылка по заявке — защита от повторных SMS
- **order_views** — клики мастеров по заявке (переход/звонок/WhatsApp) — данные для воронки
- **order_files** — вложения к заявке (фото/PDF)
- **districts / master_districts** — районы (задел на будущее, сейчас не в основном флоу)

## API

Все — `/api/...`, ответы `{ success: boolean, ... }`.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/otp/send` | создаёт заявку в статусе `unverified`, шлёт SMS с кодом + ссылкой |
| POST | `/api/otp/verify` | проверяет код, помечает телефон как verified в Redis (10 мин) |
| POST | `/api/orders` | активирует заявку (нужен verified-телефон), прикрепляет файлы, уведомляет модератора в Telegram |
| POST | `/api/orders/:token/close` | закрывает заявку (владелец, по cookie) |
| POST | `/api/orders/:token/log-view` | логирует клик мастера (view/call/whatsapp) |
| GET | `/api/masters?category=` | список активных мастеров, опционально по категории |
| POST | `/api/masters/otp/send` | OTP для регистрации исполнителя (отдельный namespace от клиентского) |
| POST | `/api/masters/otp/verify` | подтверждение телефона исполнителя |
| POST | `/api/masters/register` | создаёт мастера (`is_active=false`), уведомляет модератора в Telegram |
| POST | `/api/telegram/webhook` | приём callback/текстовых команд от модератора (диспетчеризация, одобрение мастера, `/topup`) |

Плюс серверные HTML-страницы: `/` (главная), `/join` (регистрация исполнителя), `/master/:token` (баланс исполнителя), `/order/:token`, `/o/:ownerToken`, `/my-orders`, `/lang/:code`.

## Деплой

Railway, автодеплой при `git push` в `main` (репозиторий `xtenderge-beep/xtender-ge`). Домен `xtender.ge` подключён через Cloudflare. Проект в Railway называется `fabulous-luck`, сервисы: Postgres, Redis, `xtender-ge` (само приложение).

Никакого отдельного шага "собрать/задеплоить" не требуется — пуш в `main` = деплой.

## Известные ограничения

- Нет живых обновлений без перезагрузки страницы (обычные серверные страницы, без WebSocket)
- `POST /api/telegram/webhook` не защищён секретным токеном
- Используемый SMS-шлюз сам дописывает служебную строку к тексту SMS (например `NO XTENDER-94710`) — в API шлюза нет параметра для имени отправителя, разбираемся с провайдером шлюза
- SMS-шлюз работает по `http://`, не `https://` — креды и текст сообщения идут в незашифрованном виде
- Мастерам, уже проявившим интерес к заявке, не приходит SMS при её закрытии клиентом (осознанное решение)
- Пополнение баланса исполнителя полностью ручное (перевод + команда `/topup` от модератора в Telegram) — нет онлайн-оплаты картой
